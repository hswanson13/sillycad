Build a minimal parametric 3D CAD desktop app in Python. Keep it as simple as possible: a small, readable codebase beats extra features or abstractions. I'm comfortable with Python and will run and test the GUI myself.

## Goal
An app where I can:
1. Create a 2D sketch on a base plane (XY, XZ or YZ, with an optional offset).
2. Draw lines, arcs and circles and constrain them with a geometric constraint solver.
3. Turn closed sketch profiles into solids with Pad (extrude), Pocket (cut) and Revolve.
4. Orbit, pan and zoom the model in a 3D viewport.
5. Save and reopen the parametric model, and export the result as STL.

## Stack (use exactly this; ask me before swapping anything)
- Python 3.12 in a conda environment defined by environment.yml (conda-forge).
- pythonocc-core (conda-forge) for geometry: OCCT B-rep modeling, booleans, tessellation, STL writing. Use its Qt viewer widget OCC.Display.qtDisplay.qtViewer3d for the 3D view; call OCC.Display.backend.load_backend("pyside6") before importing it.
- PySide6 for the GUI.
- planegcs (pip, installed inside the conda env) for 2D constraint solving. It is a Python binding of FreeCAD's PlaneGCS solver. Dimension values must be created with add_fixed_param(); add_param() creates a free variable the solver is allowed to change. Use dof() and diagnose() for constraint status and conflict reporting.
- pytest for tests. No other dependencies without asking.

## Architecture (standard CAD practice)
- Parametric feature history: the document is an ordered list of features (Sketch, Pad, Pocket, Revolve). The 3D shape is always regenerated by replaying that list (recompute) and is never edited directly. Editing an earlier feature recomputes everything after it.
- Strict core/GUI split: a `core` package with zero Qt imports (document, sketch model, solver wrapper, features, file I/O, STL export) and a `gui` package on top. Everything in core must be testable headless.
- Model objects are plain dataclasses with stable IDs for sketch entities, constraints and features. The GUI refers to things by ID, never by object identity across recomputes.
- Every user edit is a command on a QUndoStack (undo/redo).
- Units are millimetres and degrees in the model, the UI and the file; convert to radians only at the OCCT/solver boundary. Keep tolerances in one constants module.
- Native file format: JSON of the feature list with a "format_version" field. STL is export-only.
- Sketches attach only to base planes (with offset), never to faces of the solid. This deliberately avoids the topological naming problem.

## Sketcher
- A dedicated 2D sketch editor (QGraphicsView) opens when creating or editing a sketch, instead of sketching inside the 3D view. It has a grid, zoom/pan and snapping to existing points. The origin and the two sketch axes can be referenced in constraints.
- Geometry: point, line, arc (center/start/end), circle, plus a construction toggle. Construction geometry is ignored for profiles but can serve as a revolve axis.
- Constraints: coincident, horizontal, vertical, parallel, perpendicular, equal (length/radius), point-on-line, tangent (line–arc, arc–arc), midpoint, fix. Dimensions: length/distance, horizontal distance, vertical distance, angle, radius, diameter.
- Interaction: select entities, then click a constraint button or press its shortcut. An invalid selection shows a status-bar message. Dimensions show as labels; double-click one to edit its value.
- Re-solve after every change, and live while dragging a point. Show the remaining degrees of freedom in the status bar. Color geometry: default when under-constrained, green when fully constrained, red for conflicting/redundant constraints (list them using diagnose()). If a solve fails, revert to the last good state instead of leaving broken geometry.
- Profiles: closed loops of non-construction edges become faces, and loops inside other loops become holes. Report open or self-intersecting profiles clearly instead of crashing.

## Features
- Pad: profile, length, reversed, symmetric.
- Pocket: profile, length or through-all, reversed; subtracts from the body.
- Revolve: profile, axis (a sketch axis or a construction line), angle (default 360°); additive. Reject axes that cross the profile.
- A single solid body. The first solid feature must be additive. A feature that fails is marked with an error in the tree, and the last valid shape stays on screen.

## Main window
- Feature tree on the left (double-click to edit parameters or reopen a sketch; rename; delete). 3D viewport in the center.
- Toolbar: New Sketch, Pad, Pocket, Revolve, Undo/Redo, Fit All, standard views (front, top, right, isometric).
- Show the base planes and an origin trihedron. Draw sketches as wires in 3D, with a visibility toggle.
- File menu: New, Open, Save, Save As, Export STL (binary, with a dialog for linear/angular deflection and sensible defaults).

## Engineering standards
- Type hints, docstrings on public functions, ruff for linting and formatting. Small modules; no plugin system or speculative abstraction.
- Use `logging`, not print. Catch OCCT and solver exceptions at feature/command boundaries and show them to the user.
- Headless pytest tests:
  - Solver: a fully constrained rectangle gives the expected coordinates; a conflicting constraint is detected.
  - Features checked by volume: a 40×20 rectangle padded 10 mm is 8000 mm³; a pocket removes the expected volume; revolving a rectangle gives the expected cylinder/annulus volume.
  - Save → open → recompute gives the same volume.
  - STL export writes a non-empty file with a plausible triangle count.
- README with setup (conda env create -f environment.yml), run and test commands.

## Out of scope (do not build)
Assemblies, fillets/chamfers, patterns, sketching on faces, splines, STEP/IGES, multiple bodies, materials, plugins.
